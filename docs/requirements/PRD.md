## 1. 产品目标

WorkManager 是一款供个人使用的 Windows 本地工作管理软件。它的首要目标不是简单记录待办，而是让用户随时清楚地看到：

- 哪些工作已经完成；
- 哪些工作今天有推进但尚未完成；
- 哪些工作没有执行；
- 哪些工作仍在进行中、待安排或等待补充进度；
- 每项工作的历史进度是否被完整保留。

**最重要的产品价值：真实、清楚地记录“做了什么”和“没做什么”。** 系统不得为了提高完成率或美化日报而推断工作已完成。

## 2. 产品原则与范围

### 2.1 产品原则

1. **本地优先：** 工作数据保存在用户自己的电脑，不上传云端，不依赖远程服务。
2. **单用户：** 第一版面向个人本地使用，不做企业多用户、团队协作或账号体系。
3. **状态与执行记录分离：** 工作事项的整体生命周期状态，与某个工作日是否执行，是两类不同数据。
4. **历史可追溯：** 每日执行记录追加保存，不覆盖之前日期的记录。
5. **用户确认优先：** 系统不擅自将工作标记为完成或放弃。
6. **严格路径边界：** 应用管理的数据、缓存和运行文件放在 D 盘便携目录，不静默写入 C 盘。
7. **附件安全：** 只管理原始文件路径，不复制、上传或删除用户的原始文件。
8. **完全自研：** 可以研究开源项目的架构和产品行为，但不复制或移植其源代码。

### 2.2 第一版范围

用户 2026-11-25 确认的第一版范围（对应 [开发计划书](../development/DEVELOPMENT_PLAN.md) M0～M6）：

- 项目和工作事项管理，包括工作链接、轻量子任务和状态变化历史；
- 待安排、未开始、进行中、已完成、已放弃生命周期，允许恢复已放弃工作（具体恢复规则待确认，见第 12 节）；
- 全局优先级、多个手动置顶、拖动置顶顺序、每日计划顺序和当前工作管理；
- 今日、未来 7 天和待安排工作视图，交付工作总览、今日工作、未来 7 天、待安排四个真实业务页面；
- 工作切换、暂时跳过和待跟进；进度记录追加保存做了什么、当前进度、问题、解决方案和下一步；
- 中国大陆工作日历、到岗记录和上一个工作日复盘；
- 日报、周报和月报；
- 历史工作与执行记录查询（按工作事项、项目、日期、状态）；
- 原始附件路径关联；
- 本地 SQLite 存储、D 盘便携运行；
- 数据保留与清理；
- Windows 托盘后台运行和提醒、用户设置的开机启动、用户主动授权后的 Windows Toast。

### 2.3 非目标与第一版明确排除项

以下内容不属于第一版范围；除非用户以后明确提出，不实现，也不为它们预留抽象层、配置项或数据库字段：

- 云端同步、在线账号和远程数据库；
- 多用户协作、团队看板和权限角色；
- 企业权限系统、多租户；
- 六位数字应用密码、应用锁屏、SQLCipher、DPAPI（见 DEC-028）；
- 复杂插件系统、通用扩展框架；
- 重复工作和周期任务；
- 未经用户确认的截止日期提醒；
- 未经用户确认的单实例系统；
- 不必要的图表和完成率；
- 为假设性未来需求预留的抽象框架；
- 未经用户授权的文件上传；
- 通过 AI 或规则自动推断并确认工作完成；
- 直接复制第三方开源项目的源代码。

**注意：** 开机启动已由用户明确提出，属于第一版范围（由用户设置），不属于排除项。

## 3. 运行环境与部署要求

### 3.1 Windows 便携版

- 目标系统为 Windows 10。
- 交付绿色便携版，解压到 D 盘后双击 EXE 即可运行，不要求传统安装流程。
- 默认目录为 `D:\WorkManager\`。
- 用户移动整个 WorkManager 文件夹后，程序应根据 EXE 所在目录重新定位数据目录。
- 开机启动配置如果仍指向旧位置，应在用户从新位置启动后提示或自动修复，不得因此删除或覆盖数据库。

### 3.2 D 盘数据边界

以下应用管理的数据必须放在便携目录的 D 盘范围内：

- 普通 SQLite 数据库；
- 数据库版本迁移与完整性检查；
- WebView2 用户数据目录；
- 缓存、日志、临时文件；
- 备份（具体备份策略待确认）；
- 应用配置和其他运行时生成文件。

程序不得静默回退到 `%APPDATA%`、`%LOCALAPPDATA%`、系统 Temp 或 C 盘其他位置保存上述数据。若 D 盘路径不可用或不可写，应明确报错并停止相关操作，而不是偷偷改变存储位置。

### 3.3 Windows 系统集成

- **托盘与后台运行：** 点击窗口关闭按钮时隐藏到系统托盘，不退出进程；后台继续运行和发送复盘提醒；只有用户主动执行退出操作才完全停止。
- **开机启动：** 支持用户自行设置是否开机启动；默认不强制开启；用户移动便携目录后，启动项路径应可修复；不得在启动参数中传递工作内容或其他敏感数据。
- **Windows Toast：** 默认使用纯便携模式，不创建开始菜单快捷方式。若用户主动开启完整 Windows Toast 通知，必须在开启前说明需要创建的快捷方式路径及用途，并取得明确授权。只允许创建启用该功能所必需的系统集成文件，并提供关闭和清理入口。
- **单实例系统：** 未经用户确认，第一版不实现单实例系统。

## 4. 信息架构与核心页面

### 4.1 工作总览（Dashboard）

工作总览是程序默认首页。页面优先级已经由用户于 2026-11-18 确认，必须以“今天要做什么、今天已经做完什么”为第一视觉焦点。

首页主要区域：

- **当前工作：** 单独突出显示唯一当前工作，提供“切换工作”和“暂时跳过”操作。
- **今天要做：** 展示今日计划中尚未完成的事项。
- **今天已完成：** 展示用户明确确认已完成的事项。
- **上个工作日复盘：** 显示上一个工作日的复盘状态和待确认数量，提供开始/继续复盘入口。
- **待跟进：** 展示等待补录进度、暂时跳过或用户明确标记跟进的事项；没有数据时隐藏该区域。

布局要求：

- 当前工作位于上方并独立呈现。
- “今天要做”和“今天已完成”并列展示，标题和工作名称清晰可读。
- 复盘和待跟进属于次级信息，不得抢占今日工作列表的视觉焦点。
- 当前工作不得在“今天要做”列表中重复出现。
- 不以完成率、统计图表或大量指标替代真实工作清单。

完整布局、视觉规范和验收要求以 [WorkManager UI 设计规范](../design/UI-DESIGN-SPEC.md) 及其中的用户确认原型图为准。

### 4.2 工作视图

至少提供：

- **今日工作：** 当天计划执行的工作，页面突出当前工作、待完成和已完成两组清单；
- **未来 7 天：** 未来七个自然日的计划；
- **待安排：** 尚未安排具体工作日期的事项；
- **全局工作列表：** 按整体优先级查看工作事项；
- **历史记录：** 支持按工作事项、按项目、按日期、按状态查询历史工作、每日执行情况和进度。

第一版 M2 交付的真实业务页面为：**工作总览、今日工作、未来 7 天、待安排**。所有页面必须使用真实数据，不展示虚构内容；沿用已确认的紧凑 UI 原型，不重新设计整套 UI。

工作视图中的日期按固定业务时区 `Asia/Shanghai` 解释。

## 5. 项目与工作事项

### 5.1 项目

- 用户可以创建、编辑和归档项目。
- 工作事项可以关联一个项目，也可以暂时不归属项目。
- 项目归档不应自动删除其工作历史。

### 5.2 创建工作事项

- 新建工作事项默认进入“待安排”。
- 用户可为工作事项填写标题、所属项目、重要程度（1～5）、紧急程度（1～5）、截止日期、描述、工作链接和轻量子任务等信息。
- 允许批量创建。
- 一次创建时若选择多个项目，应为每个项目创建一条独立工作事项记录；每条记录拥有独立状态、进度、日志、计划和附件关联，不能让多个项目共享同一条可变工作记录。
- 同一标题不代表同一条工作记录。
- 工作链接只作为工作事项的一个字段保存；第一版不自动抓取链接内容、不读取链接页面，也不上传链接。

### 5.3 工作事项整体状态

| 状态 | 含义 |
|---|---|
| 待安排 | 已创建，但尚未安排到具体工作日期 |
| 未开始 | 已安排，但尚未实际开始 |
| 进行中 | 已开始，尚未确认完成 |
| 已完成 | 用户明确确认工作完成 |
| 已放弃 | 用户明确执行放弃操作 |

状态规则：

- 创建工作事项时默认“待安排”。
- 安排到日期后可进入“未开始”。
- 用户开始处理或复盘确认有推进时，可进入“进行中”。
- 只有用户明确确认完成，才允许进入“已完成”。
- 只有用户明确放弃，才允许进入“已放弃”。
- 状态变化历史必须可追溯，记录旧状态、新状态、发生时间和事件类型；历史记录不得被覆盖。
- 允许恢复已放弃的工作；恢复后的具体目标状态、是否重新参与自动排序以及历史记录规则必须由用户确认（OPEN-012），AI 不得自行编造。
- 子任务全部勾选，不自动将工作事项标记为完成。
- 某天没有执行，不代表工作事项整体状态发生变化。
- 暂时跳过当前工作，不代表放弃该工作。

## 6. 优先级、计划与当前工作

### 6.1 全局优先级

- 每项工作有重要程度和紧急程度，初始范围均为 1–5。
- 自动排序初始评分为 `importance + urgency`。
- 截止日期不参与自动优先级评分；第一版不实现未经用户确认的截止日期主动提醒，截止日期只作为字段保存和展示。
- 支持同时手动置顶多个工作。
- 用户可以拖动调整置顶顺序，置顶顺序必须持久化并跨天保留。
- 工作完成后自动取消置顶。
- 用户可以主动取消置顶。
- 已置顶事项按用户设定的顺序排列；未置顶事项按自动优先级排序。
- 同分时使用稳定的次级排序规则，避免列表无故跳动。

### 6.2 每日计划

- 每个工作日期有独立的计划列表。
- 同一项工作可以安排到多个日期，不同日期的计划互不共享顺序。
- 支持查看今日工作和未来 7 天计划。
- 用户调整某天计划顺序，只改变当天的执行顺序，不改变全局优先级和其他日期的顺序。
- 全局优先级排序和每日计划排序必须分开存储。

### 6.3 当前工作

- 同一时刻只允许存在一个“当前工作”指针。
- 用户可以将一项工作设为当前工作。
- 切换当前工作时，应记录切换事件，保留切换前后的工作关系。
- 暂时跳过当前工作时，原工作仍保持“进行中”，历史进度不丢失。
- 被跳过的工作进入“待跟进”，用户可以稍后补充本次处理结果。
- 多次切换或跳过应形成多条历史事件，不得覆盖旧事件。

### 6.4 工作进度记录

工作进度按追加方式保存，旧记录不得被覆盖。每次记录至少包含：

1. 做了什么；
2. 当前进度；
3. 遇到的问题；
4. 解决方案；
5. 下一步准备做什么。

切换工作或暂时跳过工作后，用户可以为被跳过的工作补充进度。历史进度记录必须保留，直到按数据保留规则清理。

## 7. 每日工作复盘

### 7.1 复盘日期规则

- 复盘发生在**下一个工作日的设定上班时间**，不是前一天下班时。
- 每次只复盘上一个工作日。
- 周一复盘上周五；普通周六、周日不单独产生复盘任务。
- 公司安排的周末工作日必须能够正确参与工作日计算。
- 工作日历必须支持中国大陆法定节假日、官方调休工作日、周末加班和公司临时调整；用户手动覆盖优先级最高。
- 若存在未完成的历史复盘，优先恢复最早的未完成复盘，并从已确认的位置继续，避免丢失或重复询问。
- 工作日历和日期计算统一使用 `Asia/Shanghai`。

### 7.2 提醒规则

- 从设置的上班时间开始提醒。
- 未完成复盘时，每 5 分钟提醒一次。
- 用户完成复盘后立即停止提醒。
- 当日 18:30 停止提醒。18:30 是提醒时段截止，不是下班复盘触发时间。
- 到 18:30 仍未完成的复盘，保留已确认进度，下一个工作日从断点继续。
- 应用在上班时间之后启动且存在待复盘时，立即补发一次提醒。
- 电脑从睡眠恢复时，只触发一次补偿提醒，不连续补发所有错过的提醒。
- 系统通知默认只显示通用提醒，不展示工作标题、客户或项目名称。

### 7.3 逐项复盘

对上一个工作日的计划事项，用户可以选择：

| 结果 | 含义 | 对工作事项整体状态的影响 |
|---|---|---|
| 已完成 | 当天完成，并由用户明确确认 | 用户确认后更新为已完成 |
| 有推进，未完成 | 当天做了工作，但仍未完成 | 保持或更新为进行中 |
| 没做（未执行） | 当天没有做这项工作 | 不改变整体状态 |

复盘结果是按工作日期记录的执行事实，不能替代工作事项生命周期状态。

### 7.4 计划外工作补录

- 允许用户补录昨天实际做过、但昨天没有加入计划的工作。
- 补录时可以创建工作事项、关联项目并填写简要进度。
- 补录记录应归属实际发生的工作日期。
- 不覆盖其他工作事项的历史执行记录。

### 7.5 “昨天没有工作”

如果昨天确实什么都没有做，用户可以直接选择“昨天没有工作”结束复盘。

系统应：

- 将该工作日期记录为无工作/无执行；
- 若该日已有计划事项，为其保留“未执行”结果快照；
- 不改变这些工作事项的整体状态；
- 不清空之前的工作进度和日志；
- 完成该日复盘并停止提醒。

### 7.6 整日跳过复盘

用户可以明确跳过整日复盘。跳过只更新复盘记录状态，不自动将任何工作事项标记为已放弃，也不修改其整体生命周期状态。放弃工作必须是独立操作。

### 7.7 到岗记录

- 应用提供「我已到工位」按钮，用于记录用户实际到岗。
- 实际到岗时间与计划上班时间必须分别保存，不能用一个时间覆盖另一个时间。
- 到岗记录服务于复盘和工作日历判断，不改变工作事项生命周期状态。

## 8. 日报、周报和月报

### 8.1 日报

系统每天自动生成日报，重点回答“做了什么、没做什么”。日报至少包含：

- 当日计划工作数量；
- 已完成数量；
- 有推进但未完成数量；
- 未执行数量；
- 计划外补录工作；
- 项目分布；
- 简要进度；
- 复盘是否完成、跳过或尚未确认。

如果复盘被跳过或尚未完成，日报必须明确标记“复盘未确认”，不能伪装成完整日报。

### 8.2 周报和月报

用户可以按自然周、自然月查看工作完成情况，至少支持：

- 期间涉及的工作事项；
- 期间完成的工作事项；
- 期间有推进但未完成的工作；
- 期间未执行的工作；
- 各项目工作分布；
- 每日执行记录和进度摘要；
- 未完成事项及后续计划。

### 8.3 统计口径

必须区分：

1. **工作事项数量：** 按唯一工作事项 ID 统计。
2. **每日计划次数：** 按工作日期与工作事项的组合统计。
3. **每日执行次数：** 按每日复盘明细统计。
4. **完成工作数量：** 只统计生命周期状态已进入“已完成”的唯一工作事项。

例如，同一项工作连续推进五天，工作事项数量仍为 1，每日执行次数为 5。不得把两种口径混为一个完成数量或完成率。

## 9. 历史记录与数据保留

### 9.1 工作档案

- 未完成和进行中的工作长期保留，不自动清理。
- 已完成和已放弃的工作档案保留 3 个月，之后按确认的清理规则删除工作档案及其详细进度日志、关联文本/SQL/链接和附件路径关联。
- 三个月按日历月还是固定天数计算，需在实现前确定边界规则。

### 9.2 每日记录

- 每日计划快照、每日复盘明细、每日执行日志和日报历史摘要独立于工作档案保存 1 年。
- 清理工作档案时，每日快照仍应保留足以还原当时工作标题、项目名称和执行结果的信息。
- 历史日报不能依赖已经删除的工作档案外键才能展示。

### 9.3 附件原始文件

- WorkManager 只保存用户原始文件的路径和展示信息。
- 不复制文件内容，不读取附件正文，不上传文件。
- 用户打开附件时，通过系统默认程序打开原始文件。
- 路径失效时提示用户重新选择，不删除原文件。
- 三个月后清理时，只删除 WorkManager 内部的附件关联/路径记录。
- **无论工作档案清理、附件记录清理还是数据库维护，都绝不删除、移动、覆盖或重命名磁盘上的原始附件文件。**

## 10. 数据存储与隐私

### 10.1 本地数据存储

- 第一版使用普通 SQLite 数据库，不使用 SQLCipher。
- 不实现六位数字应用密码、应用锁屏或 DPAPI 密钥保护。
- 数据库文件位于便携目录：`data/database/work.db`。
- 数据库、WAL/SHM、缓存、日志、临时文件、WebView2 用户数据和备份均按便携路径规则放在 D 盘。
- D 盘目录不可用或不可写时，必须明确报错；不得静默回退到 AppData、LocalAppData 或系统 Temp。
- 用户接受普通 SQLite 文件可被拥有相应文件访问权限的人直接读取的风险。

### 10.2 数据完整性与异常保护

- 所有多表写入使用明确的 SQLite 事务边界。
- 数据库结构变化必须通过版本化 migration 管理。
- migration 失败必须回滚；不得将数据库标记为新库或自动覆盖原库。
- 数据库损坏、磁盘空间不足或写入失败时，保留原始数据库文件并显示可理解的错误。
- 数据库备份和恢复必须纳入产品开发；备份频率、轮转数量和保留策略在实施前单独确认。
- 不得把“本地存储”描述成“加密存储”。

### 10.3 数据隐私

- 核心工作管理、复盘、搜索和报表在本地完成。
- 不上传工作内容、附件、数据库或备份。
- 不默认接入云同步、遥测或第三方分析服务。
- 第三方依赖必须单独审查许可证和运行时行为。

## 12. 待确认事项

以下事项尚未形成用户最终决策，必须显式保留为 OPEN；AI 不得自行决定，也不得阻塞与其无关的已明确功能：

1. **备份方式、频率和轮转数量。**
2. **备份恢复确认流程及过期数据处理**（含备份是否纳入数据清理范围）。
3. **上班时间默认值。**
4. **中国大陆节假日、调休日历数据来源和更新机制。**
5. **三个月保留期限按自然月还是固定天数。**

补充待确认事项（由用户 2026-11-25 决策引出，开发到相关任务前必须提交用户确认）：

6. **已放弃工作恢复后的具体目标状态、是否重新参与自动排序及历史记录规则（OPEN-012）。** M1-02 开发前必须由开发代理识别并提交用户确认问题，不得编造。

已由用户明确排除、如未来重新提出再确认的事项（不属于当前待决项，也不得提前实现或预留）：

- 重复工作和周期任务（OPEN-005）；
- 截止日期主动提醒及提醒形式（OPEN-013）；
- 单实例系统。

在上述事项确认前，开发实现必须使用显式默认值或保持待配置状态，不得把助手建议伪装成用户已确认需求。已由用户明确排除的第一版功能（见 2.3 节）不属于待确认事项。

## 1. 本次重制定的目标

本计划替代旧版按 T1～T6 阶段和大量细分任务推进的开发路线。新路线按完整业务能力组织，优先交付真正能日常使用的功能。

WorkManager 的目标是让我每天能够：

1. 创建工作事项并归属项目。
2. 清楚区分待安排、未开始、进行中、已完成和已放弃的工作。
3. 安排每天要做的工作，并查看未来 7 天计划。
4. 按重要程度和紧急程度管理全局优先级。
5. 明确当前正在处理哪项工作。
6. 切换工作时保留进度、问题和下一步。
7. 在下一个工作日复盘上一个工作日，准确记录做了什么、没做什么。
8. 自动生成日报，并按周、按月查看工作情况。
9. 使用中国大陆工作日历记录到岗时间，并准确判断上一个工作日。
10. 查询历史工作和进度，按自然周、自然月查看报表。
11. 管理附件路径、数据保留和备份恢复。
12. 通过系统托盘保持后台提醒，并按需设置开机启动。

**核心成功标准：真实、完整地记录工作，不丢失历史进度，不自动把未确认的工作算作完成。**

本计划是 WorkManager V1 的正式开发路线。用户 2026-11-25 最新确认的决策优先于本计划旧版本、旧文档、AI 建议和技术默认值。

## 3. 开发原则

1. **以现有代码为基础。** 不推倒重做，不重复实现已经实现的 T1-01、T1-02 能力，以及 T1-03、T1-04 已经实现但仍待独立审计的能力。
2. **先理解真实调用链。** 优先复用已有 Rust Core、数据库模型、Repository、Service、Tauri Commands、Bridge 和 Svelte 组件。
3. **最小完整实现。** 只做 PRD 和用户明确需要的功能，不为假设用户、未来需求或企业场景增加抽象、配置、依赖和复杂框架。
4. **按完整业务切片交付。** 每个任务尽量打通 UI、IPC、Core、数据库和必要验证，不把孤立页面或空接口当作交付。
5. **测试按风险实施。** 不追求测试数量或覆盖率数字；但事务、migration、路径安全、数据清理、备份恢复和防止数据丢失的关键逻辑必须验证。
6. **不牺牲数据安全。** 保留事务、migration 回滚、便携路径边界、附件原文件保护和明确错误处理。
7. **审计独立。** 开发者自测不等于独立审计；独立审计通过也不等于用户验收。
8. **不擅自扩大范围。** 未确认事项必须保持待确认或阻塞状态，不把助手建议写成用户决定。
9. **每次代码开发必须实际加载 Ponytail 和 Matt Pocock Implement Skill。** 具体要求以 AGENTS.md 和 DEVELOPMENT_PHILOSOPHY.md 为准。
10. **由 DeepSeek Harness 实际开发。** DeepSeek Harness 负责代码实现、自测和提交；ChatGPT 负责制定任务、审查证据、协调独立审计和跟踪状态，不擅自替代开发代理直接改写项目代码。
11. **以完整业务闭环作为交付单位。** 每个任务尽量打通 UI、IPC、Core、数据库和必要验证，不把孤立页面、空接口或半成品当作交付。
12. **独立审计由独立审计对话负责。** 开发代理不得自我审计；独立审计通过不等于用户验收，也不等于允许合并。
13. **不擅自合并任何 PR。** PR #8 的合并受 P2-01 合并门禁约束；任何 AI Agent 都不得自行合并 PR #8 或 PR #9，不得通过 Cherry-pick、替代 PR、强制推送、堆叠分支等方式绕过门禁。

- 子任务只实现 PRD 需要的简单清单，不扩展成独立项目管理系统。

| M3-03 | 逐项复盘与断点续接 | 每项工作支持已完成、有推进未完成、没做；支持计划外工作补录、昨天没有工作和整日跳过；未完成复盘优先恢复最早的未完成复盘；复盘不能擅自改变工作事项整体状态 |
| M3-04 | 复盘提醒 | 从用户设置的上班时间开始，每 5 分钟提醒一次；完成后停止；18:30 停止当天提醒；应用启动后发现待复盘补发一次提醒；电脑睡眠恢复后补发一次提醒；未完成复盘下一个工作日继续 |
| M3-05 | Windows 托盘与后台运行 | 点击窗口关闭按钮时隐藏到系统托盘；后台继续运行和提醒；用户主动退出才完全停止；支持用户设置开机启动；Windows Toast 默认关闭，只有用户主动授权后启用 |

阶段验收：

- 周一复盘上周五；普通周末不单独生成复盘；公司安排的周末工作日能正确参与工作日计算。
- 法定节假日、官方调休和用户手动覆盖的优先级正确，手动设置优先级最高。
- 实际到岗时间与计划上班时间分别保存，互不覆盖。
- 没做、无工作和跳过复盘都不改变工作事项生命周期状态。
- 未完成复盘优先恢复最早的未完成复盘，重启和跨工作日后进度不丢失。
- 提醒从用户设定上班时间开始、每 5 分钟一次、18:30 停止；应用启动和睡眠恢复各补发一次。
- 点击关闭按钮隐藏到托盘而不是退出；后台继续提醒；只有用户主动退出才完全停止。
- 上班时间默认值未确认前不得擅自硬编码。

## 10. M4：历史查询与报表

**目标：** 能够回答过去做了什么、哪些工作有推进、哪些工作没有执行。

| 任务 | 内容 | 核心验收 |
|---|---|---|
| M4-01 | 历史查询 | 支持按工作事项、按项目、按日期、按状态查询历史工作和执行记录 |
| M4-02 | 日报 | 自动生成并保留日报；至少包含今日计划、已完成、有推进未完成、未执行、计划外工作、项目分布、简要进度和复盘状态 |
| M4-03 | 周报、月报和统计口径 | 按自然周和自然月统计；区分唯一工作事项数量、每日计划次数、每日实际执行次数和最终完成工作数量；不得把连续五天执行同一工作统计成五项工作 |

阶段验收：

- 按工作事项、项目、日期、状态四种维度都能查到真实历史。
- 复盘未完成或跳过时，日报明确标记“复盘未确认”。
- 周报按自然周、月报按自然月统计。
- 同一工作连续推进五天，工作事项数量为 1，每日计划次数和执行次数按实际记录，最终完成工作数量按唯一完成工作统计。
- 工作档案后续清理后，一年内的历史快照仍可查询。
- 不为个人使用场景增加没有明确需求的复杂图表和完成率。

## 11. M5：附件、数据清理与备份

**目标：** 管理程序内的附件路径和数据生命周期，保护用户原始文件及数据库。

| 任务 | 内容 | 核心验收 |
|---|---|---|
| M5-01 | 附件路径关联 | 只保存原始文件路径；不复制附件、不读取正文、不上传；通过系统默认程序打开；路径失效时允许重新选择；不删除旧文件 |
| M5-02 | 工作档案与历史数据清理 | 未完成和进行中工作长期保留；已完成、已放弃工作保留三个月；到期后清理工作档案、详细日志和附件路径关联；每日计划、复盘明细、执行日志和日报历史保留一年；原始附件文件绝对不能删除、移动、覆盖或重命名；三个月按自然月还是固定天数按 OPEN-007 确认 |
| M5-03 | SQLite 备份与恢复 | 备份方式、频率、轮转、恢复确认和过期数据处理均须用户确认（OPEN-001/OPEN-002）；未确认前不得启用自动备份；使用一致性备份并进行真实恢复验证；不得让旧备份绕过数据清理规则 |

阶段验收：

- 附件只保存路径，不复制、不读取、不上传，打开方式和失效重选正确。
- 清理只删除数据库内允许删除的记录，不删除、移动、覆盖或重命名磁盘原始附件。
- 清理前可核对范围；清理失败回滚，不留下部分破坏状态。
- 未完成/进行中工作长期保留；已完成/已放弃按三个月处理；每日计划、复盘明细、执行日志和日报历史保留一年。
- 备份策略未确认前不启用自动备份，不声称已有可靠备份。
- 备份不得永久保留已过期数据而绕过清理规则。

## 1. 本次重制定的目标

本计划替代旧版按 T1～T6 阶段和大量细分任务推进的开发路线。新路线按完整业务能力组织，优先交付真正能日常使用的功能。

WorkManager 的目标是让我每天能够：

1. 创建工作事项并归属项目。
2. 清楚区分待安排、未开始、进行中、已完成和已放弃的工作。
3. 安排每天要做的工作，并查看未来 7 天计划。
4. 按重要程度和紧急程度管理全局优先级。
5. 明确当前正在处理哪项工作。
6. 切换工作时保留进度、问题和下一步。
7. 在下一个工作日复盘上一个工作日，准确记录做了什么、没做什么。
8. 自动生成日报，并按周、按月查看工作情况。
9. 查询历史工作和进度。
10. 管理附件路径、数据保留和备份恢复。

**核心成功标准：真实、完整地记录工作，不丢失历史进度，不自动把未确认的工作算作完成。**

## 3. 开发原则

1. **以现有代码为基础。** 不推倒重做，不重复实现已经完成的 T1-01、T1-02、T1-03、T1-04 能力。
2. **先理解真实调用链。** 优先复用已有 Rust Core、数据库模型、Repository、Service、Tauri Commands、Bridge 和 Svelte 组件。
3. **最小完整实现。** 只做 PRD 和用户明确需要的功能，不为假设用户、未来需求或企业场景增加抽象、配置、依赖和复杂框架。
4. **按完整业务切片交付。** 每个任务尽量打通 UI、IPC、Core、数据库和必要验证，不把孤立页面或空接口当作交付。
5. **测试按风险实施。** 不追求测试数量或覆盖率数字；但事务、migration、路径安全、数据清理、备份恢复和防止数据丢失的关键逻辑必须验证。
6. **不牺牲数据安全。** 保留事务、migration 回滚、便携路径边界、附件原文件保护和明确错误处理。
7. **审计独立。** 开发者自测不等于独立审计；独立审计通过也不等于用户验收。
8. **不擅自扩大范围。** 未确认事项必须保持待确认或阻塞状态，不把助手建议写成用户决定。
9. **每次代码开发必须实际加载 Ponytail 和 Matt Pocock Implement Skill。** 具体要求以 AGENTS.md 和 DEVELOPMENT_PHILOSOPHY.md 为准。
10. **由 DeepSeek Harness 实际开发。** ChatGPT 负责制定任务、审查证据、协调独立审计和跟踪状态，不擅自替代开发代理直接改写项目代码。

## 7. M1：完整工作事项管理

**目标：** 在现有工作事项创建能力上补齐日常管理，不重新实现创建流程。

| 任务 | 内容 | 核心验收 |
|---|---|---|
| M1-01 | 工作事项详情与编辑 | 可查看和编辑标题、项目、重要程度、紧急程度、截止日期、描述；复用现有字段，只有确实缺失的字段才新增 migration |
| M1-02 | 生命周期状态流转与历史 | 支持待安排、未开始、进行中、已完成、已放弃；只有用户明确确认才能完成/放弃；状态变更可追溯；允许按既定规则恢复 |
| M1-03 | 轻量子任务 | 可添加、勾选/取消、删除和查看完成情况；子任务全部完成不得自动完成父工作事项 |

阶段验收：

- 能完整查看和编辑一项工作。
- 工作状态只能按 PRD 规则变化。
- “未执行”或跳过复盘不能改变工作整体状态。
- 状态历史真实可查。
- 子任务只实现 PRD 需要的简单清单，不扩展成独立项目管理系统。

## 8. M2：每日工作管理

**目标：** 实现软件最核心的日常工作台。

| 任务 | 内容 | 核心验收 |
|---|---|---|
| M2-01 | 每日计划与未来 7 天 | 工作事项可安排到多个工作日期；可查看今日和未来 7 天；每日计划数据持久化 |
| M2-02 | 全局优先级与手动置顶 | 自动评分为重要程度 + 紧急程度；截止日期不参与评分；支持持久化置顶/排序；全局顺序与每日顺序分开 |
| M2-03 | 当前工作、切换和暂时跳过 | 同时只有一个当前工作；切换有历史；跳过不放弃原工作；待补充进度可追踪 |
| M2-04 | 工作进度记录 | 追加记录做了什么、当前进度、问题、解决方案和下一步；旧记录不被覆盖 |

阶段验收：

- 可以安排和调整今天及未来 7 天的工作。
- 首页和今日工作页使用真实数据，不展示虚构内容。
- 当前工作不会在待完成列表重复出现。
- 切换/跳过后原工作状态和历史进度保持正确。
- 关闭并重新打开程序后，计划、当前工作和进度记录仍然存在。

## 9. M3：每日复盘与提醒

**目标：** 在下一个工作日准确复盘上一个工作日。

| 任务 | 内容 | 核心验收 |
|---|---|---|
| M3-01 | 中国大陆工作日历与上个工作日计算 | 支持工作日、周末、法定节假日、调休和手动覆盖；日历数据来源按 OPEN-006 确认后实现 |
| M3-02 | 逐项复盘与断点续接 | 复盘上一个工作日；支持已完成、有推进未完成、未执行、计划外补录、昨天没有工作和整日跳过；未完成复盘可恢复 |
| M3-03 | 复盘提醒 | 从用户设置的上班时间开始，每 5 分钟提醒；完成后停止；18:30 停止当天提醒；未完成则下个工作日续接；启动/睡眠恢复时按 PRD 补发提醒 |

阶段验收：

- 周一复盘上周五；周末不单独生成复盘。
- 未执行、无工作和跳过复盘都不改变工作事项生命周期状态。
- 计划外工作能归属实际发生日期。
- 复盘进度在应用重启和跨工作日后不会丢失。
- 上班时间默认值未确认前不得擅自硬编码。

## 10. M4：历史查询与报表

**目标：** 能够回答过去做了什么、哪些工作有推进、哪些工作没有执行。

| 任务 | 内容 | 核心验收 |
|---|---|---|
| M4-01 | 历史工作搜索 | 按工作事项、项目、日期和状态查询历史 |
| M4-02 | 日报 | 自动生成并保留日报；展示计划、完成、有推进未完成、未执行、计划外工作、项目分布和复盘状态 |
| M4-03 | 周报、月报和统计口径 | 按自然周/自然月查看；区分唯一工作事项数、每日计划次数、每日执行次数和最终完成数量 |

阶段验收：

- 复盘未完成或跳过时，日报明确标记“复盘未确认”。
- 同一工作连续推进五天，工作事项仍统计为 1，执行次数为 5。
- 工作档案后续清理后，一年内的历史快照仍可查询。
- 不为个人使用场景增加没有明确需求的复杂图表和指标。

## 11. M5：附件、数据清理与备份

**目标：** 管理程序内的附件路径和数据生命周期，保护用户原始文件及数据库。

| 任务 | 内容 | 核心验收 |
|---|---|---|
| M5-01 | 附件路径关联 | 只保存原始路径和展示信息；支持打开、检查存在性和重新选择；不复制、不读取、不上传附件内容 |
| M5-02 | 工作档案与历史快照清理 | 未完成/进行中长期保留；已完成/已放弃按 3 个月规则清理；每日快照和日报历史保留 1 年；严格保护原始附件 |
| M5-03 | SQLite 备份与恢复 | 备份方式、频率、轮转和恢复确认流程经用户确认后实施；使用一致性备份并进行真实恢复验证 |

阶段验收：

- 清理只删除数据库内允许删除的记录，不删除、移动、覆盖或重命名磁盘原始附件。
- 清理前可核对范围，失败不留下部分破坏状态。
- 每日快照与日报保留期符合 PRD。
- 备份策略未确认前不启用自动备份，不声称已有可靠备份。
- 备份不得永久保留已过期数据而绕过清理规则。

## 12. M6：发布与最终验收

**目标：** 交付能够长期日常使用的 Windows 10 绿色便携版。

| 任务 | 内容 | 核心验收 |
|---|---|---|
| M6-01 | 绿色便携包与目录移动 | 解压即用；默认 D:/WorkManager；移动整个目录后可重新定位数据；不静默回退 C 盘 |
| M6-02 | 断网和数据完整性验收 | 断网完成核心工作流程；验证数据库完整性、异常退出恢复和 migration 失败回滚 |
| M6-03 | 提醒运行所需的最小 Windows 集成 | 只实现满足已确认提醒需求所必需的后台运行和通知能力；Toast 仅在用户主动授权后启用；不因技术建议自动增加开机启动、单实例等功能 |
| M6-04 | 最终用户验收与发布记录 | 按 PRD 验收清单完成真实 Windows 10 验收；记录版本、commit、测试结果、已知限制和数据位置 |

最终发布门槛：

- M0～M5 中所有纳入 V1 的任务已完成独立审计和用户验收。
- 核心流程在 Windows 10 实机可用。
- 断网核心流程通过。
- D 盘便携路径和 WebView2 数据目录经过实机检查；已接受的 DEC-029 TOCTOU 风险必须如实说明，不得宣称已修复。
- 数据库完整性、migration、数据清理和备份恢复（策略确认后）通过。
- 原始附件保护规则通过真实临时文件验证。
- 发布产物与 Git commit、测试报告和文档对应。

## 13. 任务依赖与执行顺序

1. **先完成 M0。** T1-03/T1-04 审计、遗留问题和分支整合完成后，才以统一 main 为基线启动 M1。
2. **M1 → M2。** 工作事项的详情、状态和子任务模型稳定后，再做每日计划和当前工作。
3. **M2 → M3。** 复盘依赖每日计划、工作状态和进度记录。
4. **M3 → M4。** 日报、周报和月报依赖真实执行记录。
5. **M1～M4 → M5。** 数据清理和备份必须建立在稳定的数据模型与历史快照上。
6. **M0～M5 → M6。** 最终发布统一验收。

未决事项只阻塞依赖它们的任务，不得成为提前开发无关功能的理由。

## 15. V1 明确不开发的内容

除非用户以后明确提出，第一版不开发：

- 六位数字应用密码、应用锁屏、SQLCipher、DPAPI。
- 云端同步、账号体系、多人协作、远程服务。
- 企业权限、多租户、插件平台和通用扩展框架。
- 重复/周期任务。
- 复杂时间追踪、工时计费、甘特图或无实际用途的统计图表。
- 未经用户确认的开机启动、单实例、额外系统集成和配置项。
- 为假设的未来需求预先增加数据库字段、抽象层或依赖。

## 16. 开发、审计和进度规则

- 新建任务说明和交给 DeepSeek Harness 的提示词必须使用 [开发任务提示词模板](DEVELOPMENT_TASK_TEMPLATE.md)。
- 每次代码任务开始前实际加载 Ponytail 和 Matt Pocock Implement Skill；按需加载 TDD、Bug 诊断或 Code Review Skill。
- 每项任务先确认当前分支、基线 commit、现有实现和允许修改范围。
- 每次只开发当前授权任务；完成后停止，不自动开始下一项。
- 测试以当前任务核心行为和真实风险为准，不追求测试数量。
- 每项代码任务提交独立分支和 PR，不直接推送 main。
- 开发自测、独立审计、用户验收分别记录。
- 审计发现问题时定向修复，不无故重复整轮开发或审计。
- 每次状态变化同步更新本计划和 STATUS；历史报告不覆盖，新增报告保留可追溯证据。
- 不得把助手建议、推测或技术默认值写成用户已确认决定。

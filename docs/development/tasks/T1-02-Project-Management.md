# T1-02 — 项目创建、编辑与归档

**任务编号：** T1-02
**状态：** 进行中（2026-11-18 已授权；任务分支已建立，业务代码尚未开始）

## 1. 目标

交付项目的创建、查询、编辑和归档能力，为后续工作事项创建与项目关联提供稳定的数据和 IPC 基础。项目归档不得删除项目记录，也不得破坏后续建立的工作历史关联。

## 2. 实施范围

### 2.1 SQLite 数据层

- 新增版本化 migration `0002_projects`，将 schema 从 v1 升级到 v2。
- 项目字段以技术架构的数据模型为准：`id`、`name`、`is_archived`、`created_at`、`updated_at`。
- migration 必须由现有 migration 引擎执行，沿用独立事务、失败回滚和 `user_version` 连续递增机制。
- 不在本任务中修改已验收的 T1-01 初始化、便携路径、WAL、PRAGMA 或异常保护逻辑，除非发现直接阻塞且先报告影响。

### 2.2 Rust Core

- 建立独立项目领域类型及项目数据访问/应用服务；不把业务规则写进 Tauri command handler。
- 至少提供项目列表查询、单项查询、创建、编辑和归档操作。
- 所有写入使用参数化 SQL；不拼接用户输入，不暴露任意 SQL IPC。
- 项目名称必须去除首尾空白且不能为空；错误使用稳定错误码和面向用户的中文消息。
- 不擅自增加未确认的业务字段、排序规则、名称唯一约束或第三方依赖。

### 2.3 Tauri IPC

- 通过类型安全 DTO 暴露项目查询、创建、编辑和归档命令。
- 同步 rusqlite 操作必须放在 `spawn_blocking` 中执行，避免阻塞 UI 主线程。
- IPC 错误沿用稳定 `{ code, message }` 结构；不返回 SQL、内部路径或敏感数据。
- 前端只能调用明确的项目命令，不允许任意文件、SQL 或系统命令接口。

### 2.4 前端 UI

- 实现项目管理 Feature，并使用 UI Design Tokens、Svelte scoped styles 和类型安全 Bridge。
- 不增加截图未包含的一级导航项；项目管理入口暂通过现有“设置”页面进入。
- 项目列表区分正常项目和已归档项目；创建/编辑表单只展示当前需求明确的字段。
- 提供加载中、空列表、错误、重复提交保护和长项目名称等状态。
- 归档必须有明确的用户操作；不得将归档误做物理删除。
- 本任务不实现工作事项、每日计划、当前工作、复盘或报表。

## 3. 数据与业务边界

- 本任务不提供项目物理删除操作。
- 归档仅更新 `is_archived` 和 `updated_at`；项目行必须继续存在。
- 项目名称不为空；PRD/技术架构没有明确规定唯一性，因此不得自行增加唯一名称约束。
- 技术设计没有定义项目描述、颜色、图标或手动排序字段，本任务不增加这些字段。
- 项目 ID 必须稳定且不依赖列表顺序；创建时间和更新时间采用 UTC RFC3339。
- 后续工作事项表建立时，应显式设计项目外键和历史快照策略；不得在本任务中提前创建工作事项表。

## 4. 验收标准

1. 全新数据库可从 schema v1 初始化并成功应用到 v2。
2. 已有 schema v1 数据库可在重启时安全升级到 v2；重复启动不会重复应用 migration。
3. 可以创建项目，返回稳定 ID、名称、归档状态和时间字段。
4. 空名称或纯空白名称被拒绝，数据库不产生空项目记录。
5. 可以查询项目列表和单个项目；正常项目与归档项目可区分。
6. 可以编辑项目名称，更新时间同步更新。
7. 归档后项目记录仍存在，`is_archived` 为真；归档操作不执行 DELETE，也不级联清除任何关联数据。
8. SQLite migration 失败时事务回滚，schema 版本不前进，原有 v1 数据保持可用。
9. Rust Core、Tauri DTO/命令、前端契约和 UI 行为一致；不向前端暴露数据库连接或任意 SQL。
10. 工作总览/今日工作最终布局不因项目管理功能而增加一级导航或统计装饰模块。
